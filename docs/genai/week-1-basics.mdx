**Core concept.** An LLM is a function: text in, text out, billed by the token. Before you reach for any framework, internalise four things — what a token *is*, what a context window *is*, why the model occasionally hallucinates, and how the bill grows. Once those are intuitive, every later abstraction (RAG, agents, fine-tuning) makes sense as a way to shape the input or constrain the output.

## 1.1 Python for Java/Kotlin developers

You're not learning programming. You're learning enough Python to read other people's AI code and write your own without fighting the syntax.

The high-impact differences from a JVM background:

- **Type hints** look like Kotlin but are advisory — `mypy` enforces them, the runtime doesn't. Use them everywhere anyway; the IDE catches mistakes.
- **`dataclass`** is the Python-stdlib `data class`. **`pydantic.BaseModel`** is the same idea but with runtime validation and JSON serialization — essential for structured LLM output.
- **`asyncio`** is cooperative concurrency. `async def` declares a coroutine; `await` is the only place control can switch. Don't confuse it with Java executors.
- **List / dict comprehensions** replace `stream().filter().map().toList()`.
- **Context managers** (`with open(...) as f:`) are the `try-with-resources` equivalent.

<CodeTabs python={`from dataclasses import dataclass
from pydantic import BaseModel
import asyncio

@dataclass
class Token:
    text: str
    index: int

class JobPosting(BaseModel):       # pydantic, validates on construct
    title: str
    company: str
    remote: bool
    salary_min: int | None = None  # | None == nullable, like Kotlin's String?

async def fetch_all(urls: list[str]) -> list[str]:
    # asyncio.gather is roughly CompletableFuture.allOf
    return await asyncio.gather(*(fetch(u) for u in urls))`} />

## 1.2 How LLMs actually work

You don't need to derive backpropagation. You need a mental model of *what the model is doing when you call it*.

A modern LLM reads your prompt as a sequence of **tokens** (sub-word chunks, ~4 characters each in English), runs that sequence through a **transformer** that pays selective **attention** to earlier tokens, and emits one token at a time. The **context window** is the maximum sequence length it can consider — current frontier models do 200K to 1M tokens, but cost and latency scale with context.

A few facts that matter operationally:

- **Tokenization is not character splitting.** "ChatGPT" might be one token; "antidisestablishmentarianism" might be six. Always count tokens with the model's own tokenizer when budgeting.
- **The KV cache** stores intermediate attention state during generation. It's why streaming is fast after the first token and why prompt caching can cut bills 50–90%.
- **Hallucinations are statistical fluency, not lying.** The model emits the *plausibly next token* given context. When facts aren't in context, it fabricates a fluent answer. Ground answers in retrieval (Week 2) or function calls (this week) to control this.
- **Latency has three regimes**: time-to-first-token (network + prompt encoding), tokens-per-second (the steady-state generation rate), and tail latency (the slow tokens). All three matter; tokens/sec alone is misleading.

## 1.3 Hands-on with raw APIs

Three small scripts, no frameworks. The point is to feel the shape of the API before LangChain hides it.

### Script A — Markdown summariser

A CLI that reads a directory of `.md` files and produces a one-paragraph executive summary of each.

<CodeTabs python={`import os, sys, pathlib, anthropic

client = anthropic.Anthropic()
for md in pathlib.Path(sys.argv[1]).glob("*.md"):
    text = md.read_text()
    resp = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=200,
        messages=[{"role": "user", "content": f"Summarise in one paragraph:\\n\\n{text}"}],
    )
    print(f"## {md.name}\\n{resp.content[0].text}\\n")`} />

### Script B — Structured output extractor

Job description → typed `JobPosting`. The key technique is forcing JSON output that matches a pydantic schema, then validating.

<CodeTabs python={`from pydantic import BaseModel
import anthropic, json

class JobPosting(BaseModel):
    title: str
    company: str
    remote: bool
    salary_min_usd: int | None = None
    must_have_skills: list[str]

prompt = f'''Extract structured data from the job description below.
Return ONLY valid JSON matching this schema:
{JobPosting.model_json_schema()}

Job description:
{job_text}'''

resp = anthropic.Anthropic().messages.create(
    model="claude-sonnet-4-6",
    max_tokens=400,
    messages=[{"role": "user", "content": prompt}],
)
parsed = JobPosting.model_validate_json(resp.content[0].text)
print(parsed)`} />

Two refinements worth knowing: **few-shot** the model with one or two correct examples in the prompt; and **retry once** if `model_validate_json` raises — frontier models slip into "Sure! Here's the JSON:" prefixes sometimes.

### Script C — Function calling

A toy assistant with three tools: `get_weather(city)`, `search_files(query)`, `run_sql(query)`. The model picks which tool to call; your code executes it; you feed the result back.

<CodeTabs python={`tools = [
  {"name": "get_weather", "description": "Current weather for a city",
   "input_schema": {"type": "object", "properties": {"city": {"type": "string"}},
                    "required": ["city"]}},
  # ... search_files, run_sql similarly
]

messages = [{"role": "user", "content": "What's the weather in Bangalore?"}]
resp = client.messages.create(model="claude-sonnet-4-6", max_tokens=500,
                              tools=tools, messages=messages)

while resp.stop_reason == "tool_use":
    tool_use = next(b for b in resp.content if b.type == "tool_use")
    result = dispatch(tool_use.name, tool_use.input)  # your code
    messages.append({"role": "assistant", "content": resp.content})
    messages.append({"role": "user", "content": [
        {"type": "tool_result", "tool_use_id": tool_use.id, "content": str(result)},
    ]})
    resp = client.messages.create(model="claude-sonnet-4-6", max_tokens=500,
                                  tools=tools, messages=messages)

print(resp.content[0].text)`} />

That loop — "call model, dispatch tool, append result, loop until done" — *is* an agent. You'll build a more sophisticated version in Week 3.
