## Overview

SQL is the one language you can't fake in an interview. A two-line query that joins three tables, filters by date, and groups by user tells the interviewer more about your data fluency than ten minutes of conversation.

The interview rubric: **read complex queries**, **write moderately complex queries from scratch**, **optimize a slow query**, **discuss tradeoffs**.

## Interview rubric (what you're scored on)

- **Read complex queries.** Look at a 30-line query and explain it in plain English.
- **Write moderately complex queries from scratch.** Multi-join + `GROUP BY` + `HAVING` + a window — 5–10 minutes, clean code.
- **Optimize a slow query.** Read `EXPLAIN ANALYZE`, name the bottleneck, propose an index.
- **Discuss tradeoffs.** When is `EXISTS` better than `IN`? When does `OFFSET` break down?

Start with **Fundamentals** if you're rusty, then jump to **Window Functions** (the modern interview separator) and **Practice**.
