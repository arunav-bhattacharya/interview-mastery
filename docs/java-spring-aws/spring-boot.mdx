# Spring Boot

Spring Boot is opinionated Spring. It removes the XML, gives you sensible defaults,
and embeds the application server so you ship a single fat jar. Interview signal
is recognizing what is **convention** and what is **your choice**.

## The mental model

```text
┌─────────────────────────────────────────────┐
│  @RestController       ← HTTP boundary       │
│        ↓                                     │
│  @Service              ← business logic      │
│        ↓                                     │
│  @Repository / JPA     ← persistence         │
└─────────────────────────────────────────────┘
```

## A minimal REST resource

```java title="UserController.java"
@RestController
@RequestMapping("/users")
public class UserController {

  private final UserService users;
  public UserController(UserService users) { this.users = users; }

  @GetMapping("/{id}")
  public ResponseEntity<UserDto> get(@PathVariable long id) {
    return users.findById(id)
        .map(ResponseEntity::ok)
        .orElseGet(() -> ResponseEntity.notFound().build());
  }

  @PostMapping
  public ResponseEntity<UserDto> create(@Valid @RequestBody CreateUserDto body) {
    UserDto created = users.create(body);
    return ResponseEntity.created(URI.create("/users/" + created.id())).body(created);
  }
}
```

## Persistence with JPA

- `@Entity` is your ORM model — keep it free of business logic.
- `@Repository extends JpaRepository<T, ID>` gives you CRUD for free.
- **`@Transactional`** scopes a unit of work; rollbacks happen on unchecked exceptions by default.
- Watch out for the **N+1 query problem** — solve with `JOIN FETCH` or entity graphs.

## Configuration

- `application.yml` per profile — `application-prod.yml`, `application-test.yml`, etc.
- Externalize secrets via env vars; never check them in.
- `@ConfigurationProperties("prefix")` for typed config classes — preferred over `@Value` for groups.

## Validation & error handling

- JSR-380 (`@NotNull`, `@Size`, etc.) on DTOs + `@Valid` on the parameter.
- Centralize error responses with `@ControllerAdvice` + `@ExceptionHandler`.

## What to mention in interviews

- **Beans are singletons** by default — careful with mutable state.
- **Constructor injection** is the recommended style; it makes the class testable without Spring.
- **Spring Profiles** for environment switching; `@Profile("test")` to swap beans.
- **Actuator** endpoints expose health, metrics, env — gate them carefully in prod.
- **Spring Security** is its own thing; understand filter chain ordering at a high level.
