Java questions in interviews split into three buckets: language, collections,
and concurrency. You don't need to know every corner — you need to know the
*decisions* well enough to defend them.

## JVM essentials

- **Bytecode** runs on the JVM; the same `.class` files work everywhere the JVM does.
- **Memory** — Heap (young + old) and Metaspace. GC pauses the world for major collections.
- **GCs** worth naming: **G1** (default), **ZGC** (low-pause), **Shenandoah**.
- **JIT** compiles hot code paths to native via tiered compilation.

## Collections cheatsheet

| Need                           | Pick                               | Why                                   |
| ------------------------------ | ---------------------------------- | ------------------------------------- |
| Ordered list, frequent access  | `ArrayList`                        | O(1) random access, cache-friendly    |
| Frequent middle insert/remove  | `LinkedList` (rare in practice)    | doubly linked                         |
| Unique unordered set           | `HashSet`                          | O(1) avg                              |
| Unique sorted set              | `TreeSet`                          | O(log n), iterating in order          |
| Key-value, unordered           | `HashMap`                          | O(1) avg                              |
| Key-value, key-sorted          | `TreeMap`                          | O(log n), `floorKey` / `ceilingKey`   |
| Stack / queue                  | `ArrayDeque`                       | faster than `Stack` / `LinkedList`    |
| Priority queue                 | `PriorityQueue`                    | min-heap by default                   |

## Concurrency primitives

- `synchronized` — mutual exclusion at the monitor level. Simple, slow under contention.
- `ReentrantLock` — same semantics but with `tryLock`, fairness, condition variables.
- `volatile` — visibility, *not* atomicity.
- `Atomic*` classes — lock-free CAS-based.
- `ConcurrentHashMap` — replaces `Hashtable`; segmented locking and CAS internally.
- **Executors** — `Executors.newFixedThreadPool(n)` for bounded concurrency; `ThreadPoolExecutor` for fine control.

## Common interview code

A bounded blocking buffer is a great way to talk about everything at once:

```java title="BoundedBuffer.java"
class BoundedBuffer<T> {
  private final Object[] buf;
  private int head, tail, count;
  private final Lock lock = new ReentrantLock();
  private final Condition notFull  = lock.newCondition();
  private final Condition notEmpty = lock.newCondition();

  BoundedBuffer(int cap) { buf = new Object[cap]; }

  public void put(T v) throws InterruptedException {
    lock.lock();
    try {
      while (count == buf.length) notFull.await();
      buf[tail] = v;
      tail = (tail + 1) % buf.length;
      count++;
      notEmpty.signal();
    } finally { lock.unlock(); }
  }

  @SuppressWarnings("unchecked")
  public T take() throws InterruptedException {
    lock.lock();
    try {
      while (count == 0) notEmpty.await();
      T v = (T) buf[head];
      buf[head] = null;
      head = (head + 1) % buf.length;
      count--;
      notFull.signal();
      return v;
    } finally { lock.unlock(); }
  }
}
```

## Pitfalls interviewers love

- **`==` vs `.equals()`** for boxed numerics and strings.
- **HashMap iteration order** — none; use `LinkedHashMap` if you need insertion order.
- **`String` immutability** — building strings in a loop? Use `StringBuilder`.
- **Checked exceptions** in lambdas — workaround: wrap or use unchecked.
- **Modifying a collection during iteration** — `ConcurrentModificationException`.
