# AWS Essentials

<Pillbar pills={[
  { label: 'services', value: 10 },
  { label: 'depth', value: 'enough to defend a design' },
]} />

You don't need certifications to discuss AWS in a system-design interview. You
need to be able to point at a service, explain when you'd reach for it, and
name one tradeoff.

## Compute

- **EC2** — virtual machines. You manage the OS and patching.
- **Lambda** — function-as-a-service. Cold starts matter, 15-minute max runtime, stateless.
- **ECS / EKS** — container orchestration; ECS for AWS-native, EKS for Kubernetes.
- **Fargate** — serverless containers, no node management.

**Pick rule of thumb**: ephemeral events → Lambda; steady-state services → containers; legacy / GPU / specialized → EC2.

## Storage

- **S3** — object storage. Eleven nines durability. Versioning, lifecycle rules, replication.
- **EBS** — block storage attached to a single EC2. Snapshots via S3.
- **EFS** — multi-attach NFS for file workloads.

## Databases

- **RDS** — managed relational (Postgres, MySQL, Oracle, etc.). Easy backups, replicas, failover.
- **Aurora** — RDS-compatible but storage layer is rewritten; faster failover, multi-AZ by default.
- **DynamoDB** — managed NoSQL. KV / document, single-digit-ms latency, scales horizontally. Pick partition key carefully — hot partitions are the #1 failure mode.
- **ElastiCache** — managed Redis / Memcached.

## Messaging

- **SQS** — at-least-once, FIFO option, distributed queue. Visibility timeout = your worker's deadline.
- **SNS** — pub/sub fan-out to many subscribers.
- **EventBridge** — managed event bus with rules / pattern matching. Schedule cron-style jobs too.
- **Kinesis / MSK** — ordered streams (Kinesis is AWS-native; MSK is managed Kafka).

## Front door

- **CloudFront** — CDN backed by edge POPs; pairs with S3 for static, with ALB for dynamic.
- **API Gateway** — REST / HTTP / WebSocket entry point; integrates with Lambda / EC2 / containers.
- **Route 53** — DNS with health checks and routing policies (latency, weighted, failover).

## IAM in one sentence

Every API call goes through an IAM policy check; least-privilege is the default;
**roles** (for services) are preferred over long-lived access keys.

## When asked "would you use AWS service X?"

- Name the service and what it gives you.
- Compare it to one alternative (managed vs. self-host, or AWS vs. open source).
- Mention one operational concern (cost, regional limits, cold starts, partition keys).
- Tie it back to the requirement that justifies it.

That's the whole answer template.
