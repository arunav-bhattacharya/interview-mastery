# Heap / Priority Queue

### What is a Heap?

A heap is a **complete binary tree** with the property that every parent is ≤ (min-heap) or ≥ (max-heap) its children. The root is therefore the global minimum or maximum.

Because the tree is always complete, it's stored compactly in an array: `parent(i) = (i − 1) / 2`, `children(i) = 2i + 1, 2i + 2`.

### Why Does It Work?

The heap invariant is local — it only mentions parents and children — yet it guarantees a global property: the root is the extreme element. That gives a priority queue with very cheap operations:

| Operation | Time |
| --- | --- |
| Peek root | `O(1)` |
| Push | `O(log n)` |
| Pop root | `O(log n)` |
| Build from array | `O(n)` |

### Mental Model

A pyramid where the smallest (or largest) value is always on top, stored as a flat array.

### When to Use

- **Top-K** anything: K largest / smallest / closest / most-frequent.
- **Streaming median** — two heaps in balance.
- **Merging K sorted streams** — one heap entry per stream.
- **Greedy scheduling** — earliest deadline, cheapest cost, shortest job first.
- **Dijkstra's shortest path**.

### Core Concept

**Bounded heap trick for top-K**:

- For the **K largest**, keep a **min-heap of size K**. On every insert past K, pop the root. The root is always the K-th largest seen so far.
- For the **K smallest**, symmetric — a max-heap of size K.

This keeps memory to `O(K)` and time to `O(n log K)` for huge streams.

### Common Mistakes to Avoid

- Building a heap of all `n` when you only need top-K. Use a bounded heap; `O(n log K)` beats `O(n log n)`.
- Reaching for a max-heap when the language only ships a min-heap → invert ordering (Java `Comparator.reverseOrder()`, Python push negated values).
- Forgetting that `peek` doesn't pop — call it, then decide whether to `poll`.
- Tuple comparison gotchas — wrap with an explicit comparator when ties matter.
