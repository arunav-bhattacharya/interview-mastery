# Trie (Prefix Tree)

### What is a Trie?

A trie is a **tree of characters**. Each node corresponds to a character; each root-to-node path corresponds to a string. Strings that share a prefix share the same path until they diverge.

Lookup / insert / "starts-with" run in `O(L)` where `L` is the string length — independent of how many strings are stored.

### Why Does It Work?

A trie exploits the fact that **prefixes overlap**. Storing 1,000 words that all share the first three letters costs roughly the same as storing the 997 distinct suffixes plus three shared nodes.

Prefix queries cost the same as exact lookup, because the answer is determined by whether the traversal reaches a node at all — a property hash maps and balanced trees cannot match.

### Mental Model

A character tree growing downward. Every stored prefix corresponds to a real path; type a prefix, walk down, see if the path exists.

### When to Use

- Autocomplete / search-as-you-type.
- Word-search boards — DFS the grid while staying on a trie node.
- Longest prefix match — IP routing, URL routing.
- When a `HashMap<String, V>` would do but you also need prefix queries.

### Core Concept

Two implementation choices for the children:

- **Fixed array** (e.g. `Node[26]` for lowercase Latin) — fast, more memory.
- **Hash map** (`Map<Character, Node>`) — efficient for large or sparse alphabets.

### Common Mistakes to Avoid

- Using a trie when a hash map would do — adds memory and complexity for nothing.
- Confusing "prefix exists" with "word exists" — always check the end-of-word flag in `search`.
- Memory bloat from fixed arrays with a large or sparse alphabet — switch to a map.
- Returning `true` from `search` for a partial path — that's `startsWith`, not `search`.
