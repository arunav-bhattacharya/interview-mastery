# Binary Search

### What is Binary Search?

A halving search on a monotonic structure. Maintain `[lo, hi]`, inspect the midpoint, and eliminate half of the range each step. `O(log n)`.

Beyond array index lookup, **binary search on the answer** is the more interesting variant: when the answer space is monotonic with respect to a feasibility predicate, you binary-search the answer instead of the array.

### Why Does It Work?

The pre-condition is **monotonicity**. If `a[mid] < target` and the array is sorted, every element to the left is also `< target` and can be discarded. The same argument generalizes to any predicate that flips from false to true exactly once.

Three indices moving inward: `lo`, `mid`, `hi`. The discarded half stays greyed out — you'll never look at it again.

### When to Use

- Input is sorted.
- Input is unsorted but the question is on a derived monotonic property — minimum capacity, maximum days, smallest valid value.
- Brute force is `O(n)` and the predicate has a single flip-point.
- Rotated sorted array.

### Common Mistakes to Avoid

- `(lo + hi) / 2` — overflows. Use `lo + (hi - lo) / 2`.
- Wrong loop condition — plain uses `lo <= hi`, boundary often uses `lo < hi`.
- Shifting the wrong bound. Draw the true/false flip on paper before coding.
- Applying binary search to a non-monotonic function.
