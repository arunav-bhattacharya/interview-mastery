# Backtracking

### What is Backtracking?

Systematic search through a tree of partial solutions. At each node, choose an option, recurse, and **undo** before trying the next. Pruning rules cut entire subtrees you know can't yield an answer.

### Why Does It Work?

Backtracking is DFS over the **solution space**. The tree of choices is implicit; you walk it depth-first, accumulating partial results in a path and pruning when a partial path violates the constraints. Correctness is from exhaustiveness; speed comes from pruning.

### Mental Model

```text
backtrack(state):
  if state is a complete solution: record it; return
  for each choice c:
    if c violates a constraint: skip   ← pruning
    apply c
    backtrack(state)
    undo c
```

### When to Use

- Enumerating permutations / combinations / subsets / partitions.
- Constraint satisfaction (N-queens, Sudoku, word break).
- Path enumeration with pruning (word search, palindrome partitioning).

### Core Concept

The "apply → recurse → undo" idiom keeps mutable state cheap. The crucial design decisions are:

1. **What's the state?** What does each recursive call need to know?
2. **What's the choice set?** What branches off each node?
3. **What's the pruning rule?** When can you abandon a subtree?

private void backtrack(int[] nums, int start, List<Integer> cur, List<List<Integer>> ans) {
  ans.add(new ArrayList<>(cur));
  for (int i = start; i < nums.length; i++) {
    cur.add(nums[i]);
    backtrack(nums, i + 1, cur, ans);
    cur.remove(cur.size() - 1);
  }
}`}

### Common Mistakes to Avoid

- Forgetting the **undo** step — state leaks between branches.
- Copying the partial path eagerly on every step instead of only when recording an answer.
- Not pruning early when constraints already broken — costs exponentially more time.
