# Graph Traversal

### What is Graph Traversal?

Graphs are vertices and edges. Most "graph" problems in interviews are really about **walking every reachable vertex once** — by breadth (BFS) or by depth (DFS). The hard part is recognizing the disguised graph (grids, courses with prerequisites, words one letter apart).

### Why Does It Work?

Both BFS and DFS visit each vertex at most once and each edge at most twice, so both are `O(V + E)`. Correctness comes from the **visited set**: a marker set when you push, never when you pop.

BFS discovers nodes **in order of edge distance** from the source — that's why BFS solves unweighted shortest path and DFS does not.

### Mental Model

The same loop, two different data structures:

- BFS → queue (FIFO) → frontier bulges outward in layers.
- DFS → stack / recursion → frontier plunges down one corridor.

<TreeViz />

For weighted graphs, swap the queue for a **min-heap** keyed on distance → Dijkstra.

### When to Use

| Use BFS when... | Use DFS when... |
| --- | --- |
| Shortest path on unweighted graph | Topological order / cycle detection |
| Level-order processing | Tree path / ancestor problems |
| Multi-source spread (rotting oranges) | Backtracking (permutations, subsets) |
| Minimum moves | Connected components |

### Core Concept

The standard "graph + visited set" template:

```text
seen = empty set
frontier = [start]; mark start seen
while frontier:
  u = pop          # front (BFS) or top (DFS)
  process(u)
  for each neighbour v of u:
    if v not in seen:
      mark v seen
      push v
```

For weighted graphs:

| Algorithm | Time | Notes |
| --- | --- | --- |
| BFS / DFS | `O(V + E)` | Both representations |
| Topo sort | `O(V + E)` | DAG only |
| Dijkstra (heap) | `O(E log V)` | Non-negative weights |
| Bellman-Ford | `O(VE)` | Handles negative edges |
| Union-find | ~`O(α(N))` per op | Connectivity / merging |

### Common Mistakes to Avoid

- Marking visited too late → BFS revisits and shortest-path guarantee breaks.
- Using DFS for unweighted shortest path → it returns *a* path, not the shortest.
- Applying Dijkstra to graphs with negative edges (silently wrong).
- Stack-overflow on deep recursion for very large graphs — switch to iterative.
