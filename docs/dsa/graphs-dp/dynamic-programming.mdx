# Dynamic Programming

### What is DP?

DP is recursion that **remembers**. You define an answer in terms of smaller versions of itself; you notice the smaller versions repeat; you cache each result the first time you compute it.

Two styles:

- **Memoization** (top-down) — write the recursion, add a cache.
- **Tabulation** (bottom-up) — fill a table from base cases up.

### Why Does It Work?

Two properties make DP applicable:

1. **Optimal substructure** — the optimal answer is built from optimal answers to subproblems.
2. **Overlapping subproblems** — naïve recursion solves the same subproblems many times.

When both hold, caching turns an exponential tree of calls into a polynomial DAG of unique subproblems.

### When to Use

- Brute force is **exponential** and the recursive calls overlap.
- The problem says **count / minimum / maximum** and you can define a state on prefixes, suffixes, indices, or a remaining budget.
- The state space is discrete and small enough to tabulate.

### Core Concept

A four-step recipe:

1. **State** — name the variables that distinguish subproblems.
2. **Transition** — `dp[state] = combine(dp[smaller])`.
3. **Base cases** — the smallest subproblems.
4. **Order** — topological order of subproblems.

| --- | --- |
| 1D linear | Climbing stairs, house robber, coin change |
| 2D grid | Unique paths, min path sum, edit distance, LCS |
| Knapsack | 0/1, unbounded, partition equal subset sum |
| Interval | Matrix chain, burst balloons |
| State machine | Stock buy/sell with cooldown |

### Common Mistakes to Avoid

- A state that doesn't actually distinguish subproblems → wrong answers.
- Off-by-one in base cases. Walk through `dp[0]` and `dp[1]` by hand.
- Wrong fill order — cell depends on cells you haven't filled yet.
- Confusing 0/1 knapsack with unbounded — the inner loop direction differs.
- Reaching for DP when the right tool is search with pruning.
