# Sliding Window

### What is Sliding Window?

A **sliding window** is a contiguous subrange that grows and shrinks as you walk. Instead of recomputing state for every window from scratch, you update it incrementally when an element enters or leaves.

### Why Does It Work?

Two adjacent windows share most of their elements. Adding the new value and subtracting the dropped one is `O(1)`, so the whole walk is `O(n)` — even though the window itself may span the full array.

### Mental Model

Two pointers `L` and `R` define the window. State that summarizes everything between them.

- **Fixed window**: `R` advances; `L = R − k + 1`.
- **Variable window**: `R` advances; when a constraint breaks, `L` advances until it holds again.

### When to Use

- Contiguous subarrays / substrings.
- Best / longest / shortest window meeting a predicate.
- Brute force is `O(n²)` and most work is **redundant** across windows.
- You can summarize a window cheaply (sum, max, small map).

### Core Concept

```text
Fixed window of size k:
  └─ track running sum / state
  └─ each step: state += a[r] − a[r − k]

Variable window:
  └─ R++ until constraint breaks
  └─ then L++ until constraint holds again
  └─ record best after every update
```

### Common Mistakes to Avoid

- Recomputing the sum / map every step instead of incrementing → `O(nk)` again.
- Off-by-one on window size: it's `r − l + 1`, not `r − l`.
- For variable windows, shrinking past the constraint and losing the best.
- Forgetting to delete a map key when count hits 0 → `len(freq)` overcounts.
