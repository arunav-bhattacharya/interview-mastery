# Matrix Traversal

### What is Matrix Traversal?

Grids are just graphs in disguise. Each cell has up to four (or eight) neighbours and you walk them with BFS / DFS — usually for shortest path, flood fill, or pattern matching.

### Why Does It Work?

The same traversal machinery from graphs applies: a visited set, a queue or stack, and a clear "neighbour" function. The only twist is that neighbours are computed from `(r, c)` offsets instead of an adjacency list.

### Mental Model

A grid is a graph where each `(r, c)` is a vertex and edges connect adjacent cells. Pick BFS for "minimum moves" and DFS for "all connected".

### When to Use

- Flood fill (Number of Islands, Surrounded Regions, paint bucket).
- Shortest path on a grid (with weights → Dijkstra; with binary cost → 0-1 BFS).
- Spiral / diagonal / rotated traversals.
- Pattern matching (Word Search, Sudoku).

### Core Concept

The 4-direction (or 8-direction) offset trick:

```text
int[][] DIRS = {{0,1}, {1,0}, {0,-1}, {-1,0}};
for (int[] d : DIRS) {
  int nr = r + d[0], nc = c + d[1];
  if (in_bounds && !seen[nr][nc] && passable) visit(nr, nc);
}
```

### Common Mistakes to Avoid

- Forgetting bounds check before reading `grid[r][c]`.
- Modifying the grid in place when the problem requires the original — clone first.
- 8 directions when the problem allows only 4 (or vice versa).
- BFS with no per-cell distance tracking when shortest path is the goal.
