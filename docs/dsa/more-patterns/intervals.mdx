# Intervals

### What is the Intervals Pattern?

Many problems boil down to **a list of `[start, end]` pairs**: meetings, ranges, intervals on a number line. The pattern almost always begins with **sorting by start** (or by end), then scanning once and merging / measuring as you go.

### Why Does It Work?

After sorting, you only need to compare each interval with the **previous** one. Overlap detection collapses to a single inequality (`prev.end ≥ curr.start`). What was an `O(n²)` pairwise comparison becomes `O(n log n)` sort plus `O(n)` scan.

### Mental Model

A number line with brackets drawn on it. Walk left to right, deciding whether the current bracket extends, ends, or starts a new merged interval.

### When to Use

- Merging overlapping intervals.
- Counting / finding the **minimum number of resources** (meeting rooms, CPUs).
- Insert / delete intervals in a sorted set.
- Calendar / scheduling conflicts.

### Core Concept

Two ideas you'll reach for most:

1. **Sort by start, then sweep** for merge / insert problems.
2. **Sort by end, then greedy** for "minimum number of arrows / removals" problems.

For meeting-rooms-II specifically: track end-times in a **min-heap** as you sweep starts.

### Common Mistakes to Avoid

- Forgetting to sort first — the algorithm only works on sorted input.
- Tie-breaking edge cases (`[1,2]` and `[2,3]` — do they touch or overlap? The problem statement decides.)
- Mutating the input array when the caller expects it untouched.
