DP is recursion that learns. If your recurrence revisits the same subproblem
multiple times, write the answer down and quit recomputing it. That's the entire
trick — the rest is naming the state cleanly.

## A four-step recipe

1. **State** — what changes between subproblems? (often: index, balance, last-action)
2. **Transition** — `dp[i] = f(dp[i-1], dp[i-2], ...)`
3. **Base cases** — the smallest inputs that don't decompose further
4. **Order** — bottom-up tabulation or top-down memoization

## Reference: climbing stairs (tabulation)

```java title="ClimbingStairs.java"
public int climb(int n) {
  if (n <= 2) return n;
  int a = 1, b = 2;
  for (int i = 3; i <= n; i++) {
    int c = a + b;
    a = b;
    b = c;
  }
  return b;
}
```

The full `dp[]` array is unnecessary once you notice the recurrence only depends
on the last two cells. This space-optimization trick — dropping from `O(n)` to
`O(1)` — earns easy points in interviews.

## Common families

| Family             | Examples                                |
| ------------------ | --------------------------------------- |
| **1D**             | Climbing stairs, house robber, coin change |
| **2D — grids**     | Unique paths, min-path-sum, longest common subsequence |
| **Knapsack**       | 0/1 knapsack, partition equal subset sum |
| **Interval**       | Matrix chain multiplication, burst balloons |
| **State-machine**  | Stock buy/sell with cooldown            |

## Practice

- **Climbing stairs** / **house robber** — 1D, two-state.
- **Coin change** — unbounded knapsack flavour.
- **Longest common subsequence** — 2D classic.
- **Edit distance** — the interview boss-fight of 2D DP.
