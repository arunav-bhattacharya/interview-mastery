# Stack

### What is a Stack?

A LIFO container. Push, pop, and peek are all `O(1)`. In Java, prefer `ArrayDeque` over the legacy `Stack` class; in Python, a plain list works; in Go, a slice.

### Why Does It Work?

Many "match each X with its closest preceding Y" problems are solved by pushing candidates and popping when a match is found. The stack stores **work that's been deferred**, in the exact order it needs to be resolved.

### Mental Model

A pile of waiting decisions. Each new element either resolves the top of the pile or extends it.

### When to Use

- Balanced parentheses, bracket matching.
- "Next greater element" / "previous smaller element" (monotonic stack).
- Expression evaluation, infix → postfix conversion.
- DFS with explicit stack (no recursion).
- Backtracking state.

### Core Concept

The **monotonic stack** trick: maintain a stack where values are strictly increasing (or decreasing). When you push a new value, pop anything that violates the order, and use those pops to compute answers.

  int n = a.length;
  int[] ans = new int[n];
  Arrays.fill(ans, -1);
  Deque<Integer> stack = new ArrayDeque<>();
  for (int i = 0; i < n; i++) {
    while (!stack.isEmpty() && a[stack.peek()] < a[i]) {
      ans[stack.pop()] = a[i];
    }
    stack.push(i);
  }
  return ans;
}`}

  val ans = IntArray(a.size) { -1 }
  val stack: ArrayDeque<Int> = ArrayDeque()

    while (stack.isNotEmpty() && a[stack.last()] < a[i]) ans[stack.removeLast()] = a[i]
    stack.addLast(i)
  }
  return ans
}`}

            ans[stack.pop()] = v

    for len(stack) > 0 && a[stack[len(stack)-1]] < v {

    }

  }

### Common Mistakes to Avoid

- Using Java `Stack` (synchronized, slow). Use `ArrayDeque`.
- Pushing values when the algorithm needs indices.
- Forgetting to handle an unmatched stack at the end (leftover open brackets).
