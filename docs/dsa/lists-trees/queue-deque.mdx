# Queue & Deque

### What is a Queue / Deque?

A queue is FIFO — push at one end, pop from the other. A **deque** ("double-ended queue") lets you push and pop at both ends in `O(1)`. Both are the underlying machinery for BFS and many sliding-window-with-extrema problems.

### Why Does It Work?

When the algorithm requires "first-seen, first-processed" — like BFS exploring the closest nodes first — a queue is the natural data structure. A deque adds the power to discard stale elements from either end while keeping `O(1)` operations.

### Mental Model

A waiting line: people join the back, leave the front. A deque is two waiting lines sharing the same line, which lets you also peek and remove from the back.

### When to Use

- BFS / level-order traversal.
- Sliding-window maximum (monotonic deque).
- Implementing rate limiters / event windows.
- Round-robin scheduling.

### Core Concept

The **monotonic deque** trick for sliding window max: store indices whose values are decreasing. The front of the deque is always the current window's max.

  Deque<Integer> dq = new ArrayDeque<>();
  int[] ans = new int[a.length - k + 1];

### Common Mistakes to Avoid

- Using a linked list as a queue and getting `O(n)` operations on a poor implementation. Use `ArrayDeque` / `collections.deque`.
- Forgetting to drop stale indices in the monotonic deque.
