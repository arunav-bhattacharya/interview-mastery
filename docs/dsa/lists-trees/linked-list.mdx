# Linked List

### What is a Linked List?

A linked list is a sequence of nodes, each holding a value and a pointer to the next. There's no random access — to read element `k`, you walk `k` nodes. The interview value is the **pointer manipulation** the data structure forces you to do carefully.

### Why Does It Work?

Linked lists trade fast index access for cheap insert/delete anywhere — as long as you already have a pointer to a neighbour. The cost of inserting or removing a node is bounded by **two pointer rewrites**, never the list's length.

### Mental Model

Three named pointers walking the list: `prev`, `curr`, `next`. The reversal trick is just **bending three arrows per step** — save `next` before you overwrite `curr.next`.

### When to Use

- Operations need `O(1)` insert/remove at known positions.
- The problem says **"in-place"** and **"constant extra space"** on a list.
- Implementing queues, deques, LRU caches.

### Core Concept

The four interview patterns:

1. **Reverse** — flip `next` as you walk.
2. **Two-pointer (fast/slow)** — middle, cycle detect, k-th from end.
3. **Merge** — dummy node + tail pointer.
4. **Dummy sentinel** — when the head may change, prepend a dummy.

### Common Mistakes to Avoid

- Forgetting to save `next` before overwriting `curr.next`.
- Returning `head` after reversing — `head` is now the tail.
- Skipping the dummy-node trick when the head may change.
