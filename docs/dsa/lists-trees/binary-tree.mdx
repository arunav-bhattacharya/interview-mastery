# Binary Tree

### What is a Binary Tree?

A binary tree is a hierarchy where each node has up to two children (`left`, `right`). Most interview tree problems are traversals plus a small amount of per-node bookkeeping.

### Why Does It Work?

Every interesting tree algorithm boils down to **recursion on subtrees**. The base case is `null`; the recursive case combines the answers from the children with the node's own value.

### Mental Model

Trees are recursion's home territory. Think: "if I had the answer for `left` and the answer for `right`, what would I do with them?"

### When to Use

- Hierarchical data — DOM, AST, file system, decision trees.
- Sorted lookups when balanced (BST, AVL, red-black).
- Range queries (segment tree, Fenwick / BIT).
- Tries (a tree of characters — see the Heap & Trie hub).

### Core Concept

The three traversal orders:

| Order | When to use |
| --- | --- |
| **Pre-order** (root → L → R) | Copy / serialize a tree |
| **In-order** (L → root → R) | Iterate a BST in sorted order |
| **Post-order** (L → R → root) | Compute / aggregate from leaves up |
| **Level-order** (BFS) | Per-level processing, shortest path |

### Common Mistakes to Avoid

- Confusing **pre-order** with **in-order** — the difference matters for BST sorted iteration.
- Forgetting the `null` base case → `NullPointerException`.
- Validating a BST by checking only immediate children (wrong) instead of carrying min/max bounds (right).
- Recursing too deep on a skewed tree — switch to iterative if depth could exceed thousands.
